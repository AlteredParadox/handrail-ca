DNS names, IP addresses, email addresses, URIs. With none, the certificate carries the common name as its one name; with no common name, it takes the first name as one.

With a password, at least 12 characters, the key is handed over encrypted with it, and whatever uses the certificate has to be given the password. handrail-ca does not keep the password or show it again. Without one the key is handed over as it is. A password made here is 20 random characters, and is the one to use for a PFX file, which guards its password less well than a PEM key does.

PEM is separate text files for the key, the certificate and its chain. A PFX file (also called PKCS #12 or .p12) is one file with all three, which is what Windows and many printers and appliances import; it always needs a password. Try the AES-256 kind first: the kind for older devices uses weak protection.

Making a CSR

On the machine that will use the certificate, with the step CLI:

step certificate create \
  git.internal.example \
  git.csr git.key --csr \
  --san git.internal.example \
  --san 10.20.0.14 \
  --no-password --insecure

Leave the last line out to have the key encrypted with a password. Or with OpenSSL:

openssl req -new -nodes \
  -newkey ec -pkeyopt ec_paramgen_curve:P-256 \
  -keyout git.key -out git.csr \
  -subj "/CN=git.internal.example" \
  -addext "subjectAltName=DNS:git.internal.example,IP:10.20.0.14"

Paste the .csr file {{if .Generate}}under "I have a CSR"{{else}}here{{end}}. The .key file never leaves that machine.
